# ReviewBar App Audit — August 10, 2026

## Scope and outcome

This audit covered the iOS app and its optional notification relay: product flows, SwiftUI data flow, Swift 6 concurrency, network trust boundaries, credential and cache persistence, Apple API pagination and error handling, Analytics import safety, relay authentication and cleanup, accessibility, dependency health, and automated coverage.

No critical security or data-loss defect was found. The existing architecture has strong boundaries: credentials use the this-device-only Keychain, Apple sessions are ephemeral and host-restricted, repositories and persistence are actor-isolated, canceled refreshes cannot repopulate a cleared session, partial endpoint failures preserve section-level cache, Analytics payloads are bounded, and relay secrets are not mixed with App Store Connect credentials.

The audit implementation concentrated on the largest day-to-day gap: quickly triaging several apps and finding actionable reviews or builds. It also removed a redundant one-item task group from the intentionally sequential Analytics importer.

## Feature candidates

The following features were considered. “Implemented” means included on the audit branch; deferred items need broader API, privacy, background-execution, or product decisions.

1. **Favorite apps — implemented.** Favorites persist locally, appear in app rows and Overview, and can be changed by swipe or toolbar action.
2. **Portfolio attention queue — implemented.** Apps with failed releases, failed/invalid builds, or unavailable sections can be filtered and are visibly labeled.
3. **Portfolio snapshot — implemented.** The Apps screen summarizes visible apps, favorites, attention items, unread reviews, and refresh recency.
4. **Full-text review search — implemented.** Search covers title, body, reviewer, and territory.
5. **Review workflow filters — implemented.** Users can isolate unread reviews and reviews with or without a developer response.
6. **Review response coverage — implemented.** Loaded-review average rating, unread count, and developer-response coverage are visible.
7. **Build search — implemented.** Build number and marketing version can be searched within the selected platform.
8. **Review sharing — implemented.** A review can be handed to the system share sheet without adding mutation access.
9. **Period-over-period Analytics comparisons — deferred.** Metrics have independent Apple data-through dates; comparison windows need explicit incomplete-coverage semantics first.
10. **Analytics CSV export — deferred.** Useful, but export retention and accidental disclosure need a deliberate privacy design.
11. **Credential-free widget — deferred.** Requires a redacted app-group snapshot and separate threat-model review.
12. **TestFlight feedback inbox — deferred.** Crash and screenshot feedback require new API resources, permission states, retention rules, and fixtures.
13. **Custom app groups/tags — deferred.** Favorites solve the immediate navigation problem with substantially less management UI.
14. **Release-time forecasting — deferred.** Device-local observations are not yet authoritative or numerous enough for responsible predictions.
15. **Background review checks — deferred.** iOS scheduling is opportunistic and Apple has no review-created webhook; notification wording must not promise real-time behavior.
16. **Bulk notification configuration — deferred.** Apple webhook role failures and partial rollback need a dedicated progress and recovery flow before bulk mutation is safe.

## Technical findings

### Security and privacy

- The App Store Connect private key and identifiers remain in a non-synchronizing, this-device-only Keychain item.
- Apple requests use short-lived ES256 JWTs, ephemeral sessions, HTTPS-only host validation, redirect validation, and bounded authentication retry.
- Dashboard, icon, Analytics, review-read, and release-history stores contain no credential material and use protected local files.
- The relay receives only notification delivery/configuration data. HMAC verification happens before JSON parsing, stored sensitive values are encrypted or hashed, and channel/installation cleanup is recoverable.
- `npm audit --omit=dev` reported zero production dependency vulnerabilities on the audit date.

### Correctness and resilience

- Dashboard and Analytics repositories are actors; UI state is explicitly main-actor isolated under complete strict-concurrency checking.
- Refresh and pagination paths check cancellation, reject repeating pagination, deduplicate resource IDs, and avoid persisting canceled partial results.
- Partial Apple endpoint failures retain valid live sections and safe cached fallbacks rather than failing the whole dashboard.
- Analytics download, inflate, parse, and aggregation paths are bounded and distinguish unavailable, empty, thresholded, and explicit-zero states.
- The Analytics importer claimed sequential behavior but wrapped every single report in a one-child task group. The audit made that flow genuinely sequential, clearer, and lower-overhead.
- Account-scoped favorite IDs are erased when the App Store Connect connection is removed.

### Accessibility and interface quality

- The app already uses Dynamic Type styles, accessibility-size reflow, native controls, descriptive labels, non-color status cues, and 44-point treatment for custom icon actions.
- The audit added semantic labeling to the app switcher and visible text/icon status for favorites and attention.
- No custom motion was found, so Reduce Motion does not require a special path today.

### Maintainability

- The project uses Swift 6 strict concurrency and modern Observation successfully.
- New unit coverage verifies preference persistence, attention classification, and composed review workflow filters.
- `AppModel.swift` remains a large coordinator, and several feature files contain multiple private helper views. Decomposition is recommended as a separate refactor with behavior held constant.
- User-facing strings are currently source literals. A string catalog is the next meaningful accessibility/internationalization investment.

## Verification and remaining manual checks

Automated verification on this branch includes the full iOS build, unit tests, UI tests, relay TypeScript checking, relay runtime tests, and the production dependency audit. Live Apple credentials are intentionally absent, so these release checks still require a controlled manual environment:

- Connect representative individual and team keys with different roles and app scopes.
- Exercise first-time Analytics request creation and delayed report availability.
- Exercise webhook creation, APNs permission denial/approval, device-token rotation, and disconnect compensation against a deployed relay.
- Validate VoiceOver focus order and share-sheet presentation on a physical iPhone.
- Publish final support/privacy URLs and listing metadata before App Store submission.
